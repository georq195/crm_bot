# CRM Telegram-бот для заявок

Telegram-бот, который собирает заявки от клиентов, хранит их в базе данных и помогает администраторам управлять обработкой: менять статусы, комментировать, искать, смотреть аналитику и выгружать данные.

## Возможности

**Клиент**
- создание заявки пошаговым диалогом (имя, контакт, описание, желаемая дата связи);
- список своих заявок со статусами и карточка заявки;
- редактирование заявки, пока она в статусе «Новая»;
- уведомления об изменении статуса заявки.

**Администратор**
- список всех заявок с фильтром по статусу, поиском по имени и контакту и пагинацией;
- карточка заявки: смена статуса (новая → в работе → выполнена / отклонена), комментарии (история статусов хранится и используется в аналитике, в карточке не показывается);
- удаление заявки;
- аналитика за периоды «сегодня», 7 дней, 30 дней, всё время;
- экспорт заявок в CSV и XLSX;
- уведомления о новых заявках, напоминания о заявках, которые долго остаются новыми, и ежедневная сводка.

## Стек

Python 3.12, aiogram 3, SQLAlchemy 2 (async) + SQLite, APScheduler, pydantic-settings, openpyxl, pytest.

## Структура

```
app/
  bot/          роутеры, клавиатуры, тексты, middleware (aiogram)
  services/     бизнес-логика без зависимости от aiogram
  db/           модели и репозитории
  scheduler/    напоминания и ежедневная сводка
  main.py       точка входа
tests/          тесты сервисов, репозиториев и сценариев бота
```

Слои: хендлеры → сервисы → репозитории → БД.

## Запуск через Docker

1. Получите токен бота: напишите [@BotFather](https://t.me/BotFather), выполните `/newbot` и скопируйте выданный токен.
2. Узнайте свой Telegram ID, например у бота [@userinfobot](https://t.me/userinfobot).
3. Создайте `.env` из примера и заполните `BOT_TOKEN` и `ADMIN_IDS`:

   ```bash
   cp .env.example .env
   ```

4. Запустите:

   ```bash
   docker compose up -d --build
   ```

База хранится в `./data/crm.db` (каталог смонтирован в контейнер), поэтому данные переживают пересборку образа.

## Запуск без Docker

```bash
python -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env        # заполните BOT_TOKEN и ADMIN_IDS
python -m app.main
```

## Переменные окружения

| Переменная | По умолчанию | Описание |
|---|---|---|
| `BOT_TOKEN` | — (обязательна) | Токен бота от @BotFather |
| `ADMIN_IDS` | — (обязательна) | Telegram ID администраторов через запятую |
| `DB_PATH` | `data/crm.db` | Путь к файлу SQLite |
| `TIMEZONE` | `Europe/Moscow` | Часовой пояс для отображения времени и границ «сегодня» |
| `REMINDER_INTERVAL_MIN` | `60` | Как часто (в минутах) проверять заявки, требующие напоминания |
| `REMINDER_AFTER_HOURS` | `4` | Через сколько часов в статусе «Новая» напоминать администраторам |
| `DAILY_SUMMARY_TIME` | `09:00` | Время ежедневной сводки (в `TIMEZONE`) |
| `LOG_LEVEL` | `INFO` | Уровень логирования |

**Ограничение:** администраторы задаются только через `ADMIN_IDS`. Роль нельзя изменить из бота; после правки `ADMIN_IDS` в `.env` нужно перезапустить контейнер (`docker compose up -d --force-recreate`; обычный `restart` не перечитывает `.env`).

## Схема базы данных

Четыре таблицы (SQLite, создаются автоматически при старте):

- `users` — `id`, `tg_id` (уникальный), `username`, `full_name`, `role` (`client` / `admin`), `created_at`;
- `requests` — `id`, `user_id`, `client_name`, `contact`, `description`, `preferred_contact_date`, `status` (`new` / `in_progress` / `done` / `rejected`), `search_text`, `last_reminded_at`, `created_at`, `updated_at`, `closed_at`;
- `comments` — `id`, `request_id`, `author_id`, `text`, `created_at`;
- `status_history` — `id`, `request_id`, `old_status` (пусто для создания), `new_status`, `changed_by`, `changed_at`.

## Демо-данные

Для знакомства с ботом можно заполнить базу тестовыми заявками во всех статусах:

```bash
python -m app.seed
# или в Docker:
docker compose run --rm bot python -m app.seed
```

Скрипту нужен только `DB_PATH` (по умолчанию `data/crm.db`; берётся из `.env` или окружения), `BOT_TOKEN` и `ADMIN_IDS` для него не требуются. Создаются два демо-клиента и демо-администратор (`tg_id` 900000001–900000003) и 12 заявок за последние ~10 дней. Если в базе уже есть заявки, скрипт ничего не добавляет и сообщает об этом, поэтому повторный запуск данные не дублирует.

## Резервное копирование

Достаточно скопировать файл `data/crm.db` (лучше при остановленном боте).

## Удаление заявок

Физическое удаление необратимо: вместе с заявкой удаляются её комментарии и история статусов. Удалённые заявки пропадают и из аналитики.

## Миграции

Миграций нет: `Base.metadata.create_all()` создаёт только отсутствующие таблицы и не изменяет существующие. При изменении схемы в разработке удалите `data/crm.db`; в production потребуется ручной `ALTER TABLE`.

## Особенности

- Время хранится в UTC, а показывается в часовом поясе `TIMEZONE`.
- Периоды аналитики 7d и 30d — скользящие окна (последние 7 и 30 суток от текущего момента), а не календарные дни; «сегодня» — текущие локальные сутки в `TIMEZONE`.
- Экспорт: CSV в кодировке utf-8-sig (корректно открывается в Excel); текстовые ячейки, начинающиеся с `=`, `+`, `-`, `@`, табуляции или возврата каретки, получают префикс `'` (кроме нормализованных телефонных номеров и корректных `@username`). В XLSX текст записывается как строки, поэтому формулы выполниться не могут.
- Состояние диалогов (FSM) хранится в памяти и теряется при перезапуске бота: незавершённые диалоги придётся начать заново.
